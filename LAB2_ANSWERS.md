## Question 2

The local server was started from the repository root with:

```powershell
python -m uv run mlflow server --host 127.0.0.1 --port 5000 --backend-store-uri sqlite:///mlflow.db --default-artifact-root ./mlruns
```

`--backend-store-uri sqlite:///mlflow.db` places tracking metadata in the local
SQLite database: experiments, runs, parameters, metric values and histories,
tags, run status, and references to artifact locations. These are structured
records about an experiment.

`--default-artifact-root ./mlruns` selects the default filesystem root for
artifacts: actual files such as model weights, MLmodel metadata, dependency
files, input examples, and the logged class mapping. They are not stored as
model bytes inside the tracking database. Both paths are relative to the
repository root in this server invocation. The UI and health endpoint returned
HTTP 200 at `http://127.0.0.1:5000`.

## Question 3

mean DVC can never version ML artifacts in other workflows. The existing DVC
pointer still tracks only `data/`.

The ignore file preserves `/data` and adds `mlflow.db`, `mlruns/`, and
`__pycache__/` (Python bytecode generated by the requested compile check).

## Question 5

`mlflow.log_param` records a configuration value fixed for a run, such as
learning rate, batch size, dataset, epochs, or seed. A parameter does not need
an epoch step. `mlflow.log_metric` records a measured numeric result, such as
loss or accuracy, that can change during training. Repeated calls with
`step=epoch` preserve the metric history at epochs 1 through 5. This script
logs `train_loss`, `val_loss`, and `val_accuracy` at each epoch and logs
`test_accuracy` after training using the held-out evaluation split.
